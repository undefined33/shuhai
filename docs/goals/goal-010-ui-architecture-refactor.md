# Goal 010: 信息架构重构 — 按用户工作流重组 UI

> **历史 Goal，不得直接执行。** v3 固定 Popup 保存、Side Panel 整理、Options 设置。

将扩展 UI 从"按功能模块堆砌"重构为"按用户任务流组织"。
不改功能逻辑，只重组页面结构和导航。

═══════════════════════════════════════════
验证标准（Goal 完成的唯一判据）：
═══════════════════════════════════════════

1. pnpm lint && pnpm typecheck && pnpm test 全部通过（测试数不能减少，当前 73+）
2. pnpm --filter @shuhai/extension run build 成功
3. 顶部导航只有 3 个 Tab：「整理书签」「收藏内容」「设置」
4. 用户能在「整理书签」内完成：浏览书签 → AI 分类 → 查看方案 → 确认移动 → 体检链接 → 处理死链，不需要跳 Tab
5. 用户能在「收藏内容」内完成：查看待保存队列 → 预览 → 写入 Vault，不需要跳 Tab
6. 所有现有功能保持可用，无功能丢失

═══════════════════════════════════════════

## 1. [Critical] 导航重构

### 当前结构（5 Tab）：

```
[书签] [方案] [导出] [体检] [设置]
```

### 目标结构（3 Tab）：

```
[整理书签] [收藏内容] [设置]
```

### 映射关系：

| 旧 Tab                  | 新位置                  |
| ----------------------- | ----------------------- |
| 书签（BookmarkTree）    | 整理书签 → 书签浏览模式 |
| 方案（ClassifyPreview） | 整理书签 → 分类方案模式 |
| 体检（HealthReview）    | 整理书签 → 链接体检模式 |
| 导出 → 书签索引导出     | 整理书签 → 工具按钮     |
| 导出 → 文章队列         | 收藏内容                |
| 导出 → Vault 管理       | 设置                    |
| 设置                    | 设置                    |

## 2. [Critical]「整理书签」页面设计

这是一个工作台，不是简单的列表页。内部有模式切换：

```
┌─────────────────────────────────────────┐
│  整理书签                                │
├─────────────────────────────────────────┤
│  📊 1469 个书签 · 106 个文件夹           │
│  ⚠️ 3 个待处理问题                       │
│                                          │
│  ┌─────┐ ┌─────────┐ ┌──────┐          │
│  │浏览 │ │分类方案  │ │链接体检│          │
│  └─────┘ └─────────┘ └──────┘          │
│  ─────────────────────────────────────  │
│                                          │
│  （当前模式的内容区）                     │
│                                          │
└─────────────────────────────────────────┘
```

### 2.1 浏览模式（默认）

- 书签树 + 搜索（现有 BookmarkTree 组件）
- 顶部操作栏：
  - [整理书签] 按钮 → 触发 AI 分类，完成后自动切到"分类方案"模式
  - [体检链接] 按钮 → 触发健康检测，完成后自动切到"链接体检"模式
  - [撤销] 按钮（如果有上次操作）
- 底部工具：
  - [导出书签索引] — 低频操作，不突出

### 2.2 分类方案模式

- 触发方式：点击"整理书签"按钮后自动进入，或手动切换
- 内容：现有 ClassifyPreview 组件
- 顶部显示："AI 建议移动 489 个书签"
- 操作完成后可切回"浏览"模式查看结果
- 如果还没生成方案，显示引导："点击「整理书签」生成 AI 分类方案"

### 2.3 链接体检模式

- 触发方式：点击"体检链接"按钮后自动进入，或手动切换
- 内容：现有 HealthReview 组件
- 顶部显示："发现 12 个死链，5 个重定向"
- 操作完成后可切回"浏览"模式

### 2.4 模式切换逻辑

- 使用内部 state（不是 URL/Tab），切换时不丢失数据
- 分类进行中 → 自动切到方案模式并显示进度
- 体检进行中 → 自动切到体检模式并显示进度
- 用户可以随时手动切换模式

## 3. [Critical]「收藏内容」页面设计

这是"保存文章/推文/微博到 Obsidian"的专属页面：

```
┌─────────────────────────────────────────┐
│  收藏内容                                │
├─────────────────────────────────────────┤
│                                          │
│  📂 Vault: ~/ObsidianVault  [更换]       │
│                                          │
│  ┌─────────────────────────────────┐    │
│  │  待保存 (3)                      │    │
│  │                                   │    │
│  │  📄 深入理解 eBPF                 │    │
│  │     example.com · 3500 字         │    │
│  │     [预览] [保存] [删除]          │    │
│  │                                   │    │
│  │  🐦 @hacker - APT 分析线程        │    │
│  │     x.com · 2 条推文              │    │
│  │     [预览] [保存] [删除]          │    │
│  │                                   │    │
│  │  📱 微博安全研究分享               │    │
│  │     weibo.com · 1 条微博          │    │
│  │     [预览] [保存] [删除]          │    │
│  └─────────────────────────────────┘    │
│                                          │
│  [全部保存到 Vault]                      │
│                                          │
│  ─────────────────────────────────────  │
│  最近保存                                │
│  • eBPF 内核追踪 — 5 分钟前             │
│  • CVE-2024 分析 — 昨天                 │
│                                          │
│  💡 在任意网页右键「保存此文章」          │
│     可提取正文到这里                      │
└─────────────────────────────────────────┘
```

### 3.1 核心内容

- Vault 目录状态（已授权/未授权）
- 待保存队列（从右键菜单收集的文章/推文/微博）
- 每条可以：预览、编辑标签、单独保存、删除
- "全部保存"批量写入
- 最近保存历史

### 3.2 空状态

如果队列为空：

```
还没有待保存的内容。

在任意网页右键「保存此文章到知识库」
或在 Twitter/微博页面右键「保存此推文/微博」
```

### 3.3 Vault 未授权状态

如果还没选择 Vault 目录：

```
请先选择 Obsidian Vault 目录
[选择目录]

选择后，保存的文章会写入该目录。
```

## 6. [Major] 状态和数据流调整

### 6.1 App.tsx 重构

```typescript
type ViewName = 'organize' | 'collect' | 'settings';
type OrganizeMode = 'browse' | 'plan' | 'health';
```

### 6.2 组件复用

- BookmarkTree → 整理书签/浏览模式（不变）
- ClassifyPreview → 整理书签/分类方案模式（不变）
- HealthReview → 整理书签/链接体检模式（不变）
- ExportPage 的文章队列部分 → 收藏内容（提取出来）
- ExportPage 的书签索引部分 → 整理书签的工具按钮
- ExportPage 的 Vault 管理部分 → 设置
- Settings → 设置（合并 Vault 管理）

### 6.3 不改的东西

- Background service worker 逻辑不变
- chrome.bookmarks API 调用不变
- AI 分类逻辑不变
- 健康检测逻辑不变
- Vault 写入逻辑不变
- Content Script 不变
- 安全消毒不变

═══════════════════════════════════════════
工作方式：
═══════════════════════════════════════════

- 优先级：导航重构（1）→ 整理书签页（2）→ 收藏内容页（3）→ 设置页（4）→ Popup（5）→ 数据流（6）
- 建议一次性重构（不要分多次，避免中间状态不一致）
- 重构完成后逐页面验证功能完整性
- 每完成一个里程碑 commit + push

═══════════════════════════════════════════
如果被阻塞：
═══════════════════════════════════════════

- 组件拆分导致 props drilling 过深 → 用 React Context 或提升状态
- Side Panel 和 Popup 共享新结构时状态冲突 → 统一用 chrome.storage 作为数据源
- 重构过程中测试失败 → 先修测试再继续
- 网络不可用无法 push → 本地 commit

最终停止时必须报告：

1. 已完成的功能列表（附 commit hash）
2. 被阻塞的功能及原因
3. 当前测试数量和通过状态
4. 新的 Tab 结构是否能正常切换
5. 所有原有功能是否保持可用
6. 需要人工介入的事项
