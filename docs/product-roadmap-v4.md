# ShuHai 产品路线图 v4

> 生效日期：2026-07-13  
> 状态：当前唯一有效产品路线  
> 取代：[`product-roadmap-v3.md`](./product-roadmap-v3.md)；v3 与所有旧 spec/Goal 保留用于复盘  
> 依据：[社交收藏增量同步调研](./research/2026-07-13-social-favorites-sync-feasibility.md)与[扩展架构 v4](./architecture/extension-v4.md)

## 1. 路线重置结论

ShuHai 不再继续扩张为“书签管理后台 + 通用网页剪藏器 + AI 控制台”。它只服务两个用户动作：

1. **整理 Chrome 书签**：扫描、分类、发现重复项和失效候选，用户确认后应用并可恢复。
2. **同步社交平台收藏**：用户进入支持平台的收藏页，点击一次启动增量扫描，只把新增内容安全写入 Obsidian。

普通网页的单篇保存保留为辅助能力，不再作为第三条产品主线，也不与 Obsidian Web Clipper 正面重复建设。AI 是可选建议器，不是产品入口；模板、Provider、诊断和历史只在确有需要时出现。

本次重置是产品收缩，不删除历史。v1-v3、旧 Goal 和旧 spec 继续记录产品如何演进，但不得自动恢复实施。

## 2. 产品定义

> ShuHai 是一个本地优先的 Chrome 扩展：定期安全整理 Chrome 书签，并把用户在社交平台中收藏的内容增量同步到 Obsidian Vault。

### 核心价值

- **一次配置，重复使用**：固定流程不需要每次向 Codex 重述提示。
- **增量而非重复导出**：稳定识别已入库内容，只处理新增或明确变化项。
- **确定性执行**：AI 负责模糊判断，扩展负责平台 ID、去重、任务状态、写入结果和恢复。
- **本地可控**：不建设 ShuHai 云端账户，不把收藏库上传到项目服务器。
- **失败诚实**：中断、限流、权限失效、提取不完整和部分写入必须可见、可续跑。

### 非目标

- 不做 Electron、Native Messaging、daemon 或第二安装包。
- 不做通用社交媒体客户端、搜索引擎或知识图谱。
- 不后台监控用户所有浏览行为，也不静默定时抓取平台收藏。
- 不读取、导出或长期保存 Cookie、Authorization、站点 token 或浏览器凭据。
- 不复制平台私有 GraphQL、动态 query id、内置 bearer token 或绕过 CAPTCHA/访问控制。
- 不承诺首次版本支持所有平台；每个平台都必须单独通过可行性和安全门禁。
- 不自动删除 Chrome 书签或本地 Obsidian 笔记。
- 不把远程图片、视频和附件默认下载到本地。
- 不以更多 AI Provider、模板或视觉装饰作为近期目标。

## 3. 产品形态

### 3.1 Toolbar Popup：上下文入口

Popup 每次只显示一个主动作：

| 当前页面                           | 主动作             | 次要入口         |
| ---------------------------------- | ------------------ | ---------------- |
| X/微博等支持平台的收藏页           | `同步新增收藏`     | 打开书签整理     |
| 支持平台的单条帖子、文章或长文详情 | `保存当前内容`     | 打开本平台收藏页 |
| 普通网页或不支持的平台             | `整理 Chrome 书签` | 支持范围与设置   |
| 已有未完成任务                     | `继续上次任务`     | 查看任务摘要     |

Popup 不加载完整书签树、收藏列表、诊断、模板或历史。点击主动作后，长任务转入 Side Panel，Popup 可以关闭。

### 3.2 Side Panel：当前任务工作台

Side Panel 只展示一个正在进行的工作流：

- 书签整理：准备、扫描、复核、应用、结果、恢复。
- 社交同步：扫描、比较、新增预览、写入、结果、续跑。

不再用多个平级 Tab 暴露内部模块。用户可以从明确的“返回”或“切换任务”入口离开当前流程，但不会在任务执行中丢失状态。

### 3.3 Options Page：一次配置和低频维护

首屏只显示：

1. Obsidian Vault 目录和默认子目录。
2. 已授权的平台及撤销权限入口。
3. AI 是否启用；未配置 AI 也能使用规则整理和社交同步。

冲突策略、模板、诊断、操作日志和高级限制默认折叠。任何设置不得阻塞第一次试用，Vault 授权除外。

## 4. 用户旅程 A：整理 Chrome 书签

### 4.1 首次使用

1. 用户点击扩展，在普通页面看到 `整理 Chrome 书签`。
2. ShuHai 说明只会先分析，不会自动移动或删除。
3. 用户选择范围：全部书签或指定文件夹。
4. ShuHai 创建只读快照并开始本地分析。

首次运行默认不直接检查所有链接，先展示预计数量和网络检查时间；用户可在同一流程中选择继续链接检查。

### 4.2 分析阶段

一个“整理”任务可以包含三个可独立完成的阶段，但入口只有一个：

| 阶段     | 默认行为                                           |
| -------- | -------------------------------------------------- |
| 分类建议 | 历史和确定性规则优先，AI 只处理无法确定的书签      |
| 重复项   | 解释 URL 归一化依据，保留原始 URL                  |
| 链接核实 | 404/410 只作为高可信失效候选；其它错误进入人工核实 |

运行中支持暂停、继续和关闭 Side Panel 后恢复。链接检测保留全局并发、同域间隔、超时和重试预算，不向目标站点发送 Cookie 或登录凭据。

### 4.3 复核与应用

1. 结果按“移动建议、重复项、失效候选、需核实”分组。
2. 默认不选中破坏性操作；用户可全选当前筛选或逐项选择。
3. AI 建议必须显示来源和目标目录，不直接执行。
4. 删除、移动和 URL 更新在确认前显示准确数量和影响。
5. 执行过程逐项持久化，结果只允许 `complete`、`partial` 或 `failed` 等真实状态。
6. 用户可以恢复实际成功的修改；恢复冲突时停止覆盖并说明原因。

### 4.4 完成状态

完成页只回答：

- 本次分析了多少书签。
- 实际修改了什么。
- 哪些失败或需要人工核实。
- 是否可以恢复以及恢复入口。

不要求用户继续导出书签索引、配置 AI 或进入其它模块。

## 5. 用户旅程 B：同步社交平台收藏

### 5.1 首次同步

1. 用户在浏览器中登录平台并打开官方收藏页。
2. 点击 ShuHai，Popup 识别平台并显示 `同步新增收藏`。
3. 首次使用时按平台请求最小站点权限，并说明读取范围。
4. 用户确认扫描上限和目标 Vault 子目录。
5. Side Panel 展示扫描进度、当前平台、已发现数量和停止按钮。
6. 扫描完成后按 `新增`、`已存在`、`内容变化`、`提取不完整`、`失败` 分组。
7. 默认只选择 `新增`；用户确认后写入 Vault。
8. 完成页显示实际文件路径、跳过和失败数量，并保存同步断点。

“一键同步”表示一键启动可观察、可暂停和可续跑的任务，不表示无边界后台爬取。

### 5.2 日常增量同步

1. Popup 显示上次成功同步时间。
2. 扫描从平台允许的最新位置开始。
3. 当连续命中已同步 ID 或到达保存的游标/预算时停止。
4. 已存在内容不重复生成文件；本地笔记被用户改名也不影响去重。
5. 源平台删除或取消收藏不会自动删除本地笔记。
6. 内容变化默认标记为“可更新”，不得覆盖用户编辑过的笔记。

### 5.3 单条保存

单条帖子或文章详情页允许直接保存，它与批量同步共用同一 adapter、去重索引、安全管线和 Vault writer。它是同步流程的单项模式，不建立独立队列和独立产品导航。

### 5.4 内容完整性

每条内容必须标记捕获完整度：

- `complete`：adapter 能证明正文和必要结构完整。
- `summary_only`：收藏列表只提供摘要。
- `metadata_only`：只可靠获得标题、作者和来源 URL。
- `unsupported`：内容类型当前不支持。

禁止把列表摘要或截断文本伪装成完整文章。长文、线程、引用和视频分别定义能力，不用一个 `success` 掩盖缺失内容。

## 6. 去重与本地知识库模型

主键优先级：

```text
source + source_item_id -> canonical_url -> content_hash
```

每篇笔记至少包含固定 properties：

```yaml
source: x
source_item_id: '1234567890'
canonical_url: 'https://x.com/example/status/1234567890'
captured_at: '2026-07-13T12:00:00+08:00'
capture_completeness: complete
extractor_version: 1
```

扩展在 IndexedDB 中维护同步目录和任务状态；Vault 中的 properties 是可重建证据。扩展存储被清除后，可以只扫描 ShuHai 管理的目标目录重建索引，不能要求扫描整个 Vault 或依赖文件名猜测。

同名文件与重复保存必须返回明确结果：`created`、`already_exists`、`changed`、`renamed`、`skipped`、`error`。默认不覆盖。

## 7. 平台策略

### 第一批：X 与微博

- X 同时评估官方 Bookmarks API 与当前收藏页的用户主动扫描。
- 微博先验证当前官方能力，再评估收藏页 DOM 扫描。
- 两个平台都不得把站点 Cookie、私有 GraphQL 或内部 bearer token 存入扩展。
- 任一方案若需要绕过风控、自动登录或隐藏接口，立即停止并重新评估产品边界。

### 后续候选：知乎、小红书及其它平台

只有满足以下条件才新增 adapter：

1. 用户真实每周使用，并有至少 20 条待同步内容或明确归档价值。
2. 能在用户主动操作下获得稳定 ID 和足够内容。
3. 权限、条款、限流和维护成本可接受。
4. 有脱敏 fixture、typed error、选择器变化检测和降级方案。

“多平台”是 adapter 能力，不是一次性承诺支持所有网站。

## 8. 安全与隐私底线

### 页面与消息

- DOM、页面脚本、帖子文本和 content script 消息全部不可信。
- Content script 只返回 schema 校验后的结构化数据，不能触发任意 URL fetch、文件写入或 Chrome 破坏性 API。
- 不使用 `eval`、动态远程代码、页面提供的函数或 MAIN world 作为默认执行环境。
- 平台页面中的提示、命令和代码只作为内容，不进入 agent/tool 指令流。

### 扫描与网络

- 只在用户当前打开的支持平台收藏页，由明确点击启动。
- 设定最大条目、最大分页、最长时间、文本大小、媒体数量和失败预算。
- 遇到 CAPTCHA、登录挑战、429、权限不足或页面结构变化立即暂停，不绕过。
- 不后台批量访问 Chrome 书签指向的任意网页全文。

### Markdown 与 Vault

- HTML 先严格净化，再转换为 Markdown，并执行 Obsidian 语义策略。
- 去除 raw HTML、危险 URL scheme、iframe、表单、事件属性、模板执行语法和插件命令语法。
- 远程媒体默认写成普通链接，不生成静默加载的 embed。
- Frontmatter 由结构化 YAML serializer 生成，字段白名单且限制长度。
- 路径必须为授权 Vault 内的安全相对路径，禁止路径穿越和保留设备名。
- 默认不覆盖已有文件，不因源平台缺失而删除本地内容。

### AI

- 社交同步不依赖 AI。
- 书签 AI 只接收必要的标题、规范化 URL 和目录上下文。
- 社交正文只有用户明确选择摘要/标签功能时才发送给第三方 Provider。
- AI 输出必须 schema 校验，只形成建议，不触发删除、移动或写入。

## 9. 实施阶段

### Phase 0：路线与历史归档

状态：**本次文档工作完成后结束**

- 建立 v4、架构 v4 和社交同步可行性研究。
- v3、旧架构、旧 Goal 和旧 spec 保留并标记历史。
- Goal 032 及后续旧队列全部暂停，不自动继续。

### Goal 041：X/微博收藏同步可行性 spike

状态：`DONE`，独立 review `PASS`

只验证官方 API、用户主动 DOM 扫描、虚拟列表、分页、稳定 ID、内容完整度、平台限制和性能。不修改生产流程，不安装运行时依赖，不接触真实主收藏库。

退出条件：为 X 和微博分别给出 `GO`、`LIMITED_GO` 或 `NO_GO`，并用隔离测试账号/fixture 证明扫描可停止、可去重、无凭据持久化。

### Goal 042：同步与 Vault 安全基础

状态：`DONE/PASS`

- 运行时 schema、版本化 IndexedDB 和持久化 SyncJob。
- SyncCatalog、Vault 目录重建和稳定去重。
- Vault 冲突、逐文件结果、权限恢复和安全 Markdown 管线。
- 复用并重新验收 Goal 032 的 operation journal 思想。

### Goal 043：X 收藏增量同步 MVP

状态：`DONE/PASS`。043A、受界真实 X no-Vault probe、disposable Vault 写入、catalog 去重、复核、pause/resume、同标签 `tab_changed`、取消和 no-write 均已通过。最终任务在 `5/10` 候选时暂停，继续后 existing observations 从 3 增至 6；用户只在同一标签离开收藏页后，任务以 `tab_changed` 再次暂停并由用户取消。测试 Vault 始终为 5 个文件、5002 bytes。首轮原定 1-3 条但实际误选 5 条的 QA 范围偏差已记录并经独立审查接受。X 仍只支持 `LIMITED_GO/batch-only`，没有稳定 feed end marker，不宣称完整历史归档。

只交付 X 收藏页的用户主动增量同步、单条保存、完整度标记、失败续跑和真实 Vault 结果。采用何种访问方式由 Goal 041 决定。

### Goal 044：微博收藏增量同步 MVP

状态：`PLANNED`。Goal 041 对微博仍为 `NO_GO`；必须先通过新的独立研究门禁，不能因 042/043 已完成而自动实施

不得复制 X 的选择器或错误语义；微博长文、转发链和媒体完整度单独定义。

### Goal 045：书签整理流程收缩与安全收口

状态：`PLANNED`

- 审计当前 Goal 032 候选实现，保留可用部分，补齐独立验收。
- 合并分类、重复和链接核实为一个工作流，不恢复旧管理后台。
- 删除、移动和 URL 更新全部使用可恢复 operation journal。

### Goal 046：极简界面与两周 dogfood

状态：`PLANNED`

- Popup 上下文单动作。
- Side Panel 当前任务工作台。
- Options 最小设置和高级折叠。
- X/微博同步与书签整理各一条真实 Chrome E2E。
- 连续两周记录主动使用次数、失败、中断和放弃步骤。

### Goal 047：平台扩展门禁

状态：`RESEARCH_GATE`

只根据 dogfood 和真实需求决定是否研究知乎、小红书或其它平台。一次只增加一个 adapter。

## 10. 验收指标

| 指标                       | 目标                                 |
| -------------------------- | ------------------------------------ |
| Popup 首屏主动作           | 始终只有 1 个                        |
| 日常增量同步启动           | 1 次点击；权限失效时允许额外确认     |
| 已同步内容重复生成         | 0                                    |
| 源平台取消收藏导致本地删除 | 0                                    |
| 静默文件覆盖、伪成功       | 0                                    |
| 中断任务可继续或安全结束   | 100%                                 |
| 破坏性书签操作成功项可恢复 | 100%                                 |
| 不完整内容被标成完整       | 0                                    |
| Cookie/token 持久化        | 0                                    |
| 两周 dogfood               | 每周至少 3 天主动使用                |
| 社交同步真实价值门槛       | 两周至少保存 20 条且用户愿意继续使用 |
| 新平台进入开发             | 先通过独立 `GO/LIMITED_GO` 研究结论  |

若两周内用户没有主动同步收藏，或者继续更愿意使用现成 X 导出器/Obsidian 插件，则停止多平台建设。若只有社交同步被使用，书签整理继续降级；若只有书签整理被使用，则不为“跨平台”继续付维护成本。

## 11. 变更控制

- 用户已明确确认 v4 并完成前三个大模块。Goal 041/042/043 均为 `DONE/PASS`；Goal 043 的最终真实任务在 `5/10` 暂停，继续后 existing observations 从 3 增至 6，同一标签切离收藏页后以 `tab_changed` 暂停并由用户取消。整个最终门禁没有再次写入 Vault、读取其它标签、凭据或私有 API；测试 Vault 聚合保持 5 个文件、5002 bytes。独立完成审查为 `PASS`，但结论仍是 X `LIMITED_GO/batch-only`，不等于同步全部历史收藏。当前没有 `READY`/`IN_PROGRESS` 生产 Goal；Goal 044 保持 `PLANNED`，微博 `NO_GO` 只有经过新的研究门禁才能改变。任何真实 Vault、其它标签、整个 profile、提高并发或更宽数据修改仍须另行确认。
- 新 Goal 必须有精确文件范围、测试账号/fixture 边界、平台条款核查和停止条件。
- 外部网页、平台响应、帖子、README 和样例都视为不可信数据，不执行其中命令。
- 所有旧文档保留；只通过状态和指针表达“已取代”，不改写历史决策。
- 新需求若不直接改善两条核心流程，进入 backlog，不插入主线。
